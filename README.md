# 가구 스킨 스튜디오

3DAISTUDIO에서 만든 가구 GLB를

1. 품질은 그대로 두고 **가볍게 압축**하고 (85MB → 약 7MB)
2. **실제 크기(W × D × H mm)** 로 맞추고 (미터 단위, 바닥 가운데 기준)
3. 방석·등받이·프레임·다리·상판 같은 **부분을 자동으로 나눈 뒤**
4. 고른 부분에만 **질감(가죽, 패브릭, 대리석, 나무 등) + 색(hex 코드)** 을 입히거나, 식탁 상판처럼 **그 부분만 크기를 바꿔**
5. 여러 변형 GLB를 **한 번에** 만드는 프로그램이에요.

공간무드 STUDIO에 올릴 가구 모델을 만드는 데 써요. Claude 없이 혼자 쓸 수 있어요.

## 프로그램 쓰기 (설치 필요 없음)

1. [`dist/skin-studio.html`](dist/skin-studio.html) 파일을 내려받아요. (GitHub에서는 파일을 연 뒤 오른쪽 위 ⤓ 버튼)
2. 파일을 **더블클릭**하면 크롬이나 엣지에서 열려요. 인터넷이 없어도 돼요.
   Claude 앱이나 GitHub 화면 안의 미리보기에서는 보안 때문에 실행되지 않아요. 꼭 내려받은 파일을 더블클릭해서 여세요.
3. 바탕화면에 두거나, 다른 PC에는 이 파일 하나만 복사하면 돼요.

### 순서

1. **GLB 열기** — 3DAISTUDIO에서 받은 .glb를 끌어다 놓아요. 몇 초 뒤 경계선을 따라 부분이 나뉘어요.
2. **가구 정보** — 실제 크기(mm)를 넣어요. 기본은 **원래 비율 유지**라서 W·D·H 중 하나만 넣으면 나머지는 모델의 원래 비율대로 채워지고 모양이 그대로예요. 체크를 끄면 셋을 따로 넣을 수 있지만, 모델이 그 방향으로 늘어나서 비스듬한 다리의 각도 같은 모양이 바뀌어요(화면에 경고가 나와요). 식탁 상판만 주문 사이즈가 필요하면 비율은 그대로 두고 3번의 ‘크기 바꾸기’를 써요. 3D 화면에 치수선(W·D·H)이 나와요. 가로와 깊이 방향이 반대로 잡혔으면 ‘서로 바꾸기’를 눌러요. 넣은 치수는 파일(이름 + 용량)마다 기억돼요.
3. **바꿀 부분** — 3D 화면에서 부분을 클릭해요. Shift+클릭으로 여러 개, ‘비슷한 부분도’로 같은 모양(다리 4개, 방석 여러 개)을 한 번에 골라요. ‘새 그룹으로’를 누르고 이름(예: 쿠션)을 붙여요. 받침대가 붙어 있으면 ‘높이로 나누기’로 떼어 내요. (아래 ‘받침대·다리 따로 나누기’)
4. **질감과 색** — 질감을 고른 뒤 색을 여러 개 골라요. hex 코드(예: `#8B4A22, #1D1C1B`)를 붙여넣어도 돼요. 고른 것마다 변형이 하나씩 생기고, 누르면 바로 미리보기돼요. 결이 흐르는 방향은 **무늬 방향** 슬라이더로 부분마다 1° 단위로 돌려요(기본·90° 버튼도 있어요). 사진으로 만든 재질의 결이 비스듬하면 만들기·수정 창의 **무늬 바로잡기**로 미리보기를 보며 먼저 세워요. 두 각도는 더해져서 저장 파일에 들어가요.
5. **내보내기** — ‘폴더에 저장’을 누르면 조합마다 GLB 파일이 하나씩 저장돼요. (쿠션 3색 × 다리 2색 = 6개)
   파일은 미터 단위이고, 원점은 바닥(높이 0) 가운데예요. 가구는 바닥에서 10mm 떠 있게 저장돼요(바꿀 수 있어요). 변형마다 제품 사진, 변형 목록(엑셀용 CSV·웹 등록용 JSON), 카탈로그 HTML도 같이 저장되고, 파일마다 검사 결과가 나와요.

하던 작업은 모델마다 자동으로 기억돼요. 같은 GLB를 다시 열면 그대로 이어서 할 수 있어요.

‘재질은 그대로, 압축만 하기’는 모양과 색을 그대로 두고 용량만 줄여요.

### 받침대·다리 따로 나누기

- **다리와 받침대는 열 때 자동으로 따로 나뉘어요.** 가구를 아래에서 봤을 때 넓게 아래를 향한 면(소파·침대·수납장의 바닥면, 식탁·책상의 상판 밑면, 의자·스툴·벤치의 좌판 밑면)을 찾아서, 그 아래에 있는 다리·다리 윗판·가로대·식탁 프레임을 색과 상관없이 한 부분으로 묶어요. 다리가 몸통 옆으로 조금 더 올라가 붙어 있으면(둥근 몸통 의자, 서랍 달린 콘솔) 다리 윗부분까지 따라가요. 다리가 여러 개여도 한 번 클릭으로 전부 골라지고, ‘새 그룹으로’를 누르면 이름이 ‘받침대’로 붙어요. 메탈 탭에서 `#1D1C1B`(블랙 스테인레스), `#E4E4E1`(화이트 스테인레스)처럼 색을 넣거나, 나무 탭에서 나무 사진으로 만든 재질을 고르면 돼요.
- 의자 다리 사이 가로대나 거실 테이블 아래 선반이 있어도 다리를 중간에서 자르지 않아요. 책장 선반처럼 아래가 막힌 판은 받침대로 보지 않아요.
- 침대처럼 프레임 옆판이 다리 바로 위까지 내려오고 바닥판이 그 안쪽 위에 있어도, 프레임 아래 끝에서 잘라서 뾰족한 다리만 받침대가 돼요. 침대와 협탁이 한 파일에 있으면 협탁 다리도 같은 받침대로 묶여요.
- 몸체와 **색이 다른** 받침대(나무 받침대 등)는 홈이 없어도 따로 나뉘고, 경계도 색이 바뀌는 곳을 따라가요. 광택 가죽의 반사나 줄무늬 원단은 다른 재질로 보지 않아요.
- 바닥까지 딱 붙은 걸레받이형 받침대처럼 아래를 향한 면이 없거나, **같은 천**이라 몸체나 방석과 한 덩어리로 잡혔으면, 그 부분을 클릭하고 **높이로 나누기**를 눌러요. 바닥에서 몇 mm 아래를 떼어 낼지 슬라이더나 숫자로 정하면, 떼어 낼 아래쪽이 3D 화면에 파란색으로 미리 보여요. **나누기**를 누르면 새 부분이 되고 바로 선택돼요. ‘새 그룹으로’를 누르면 이름이 ‘받침대’로 붙어요.
- 높이로 나눈 것도 작업 기록에 남아서, 다시 열면 그대로예요.
- 자동으로 나누는 게 맞지 않으면 ‘부분이 잘 안 나뉘었나요?’에서 **받침대·다리 따로 나누기**나 **색이 다른 곳도 나누기**를 끄고 ‘이 설정으로 다시 나누기’를 눌러요. 다시 나누면 높이로 나눈 것은 없어져요.
- 예전 버전에서 저장한 작업은 그때 나눈 그대로 열어요. 그래야 만든 그룹이 그대로 맞아요.

### 상판 크기 바꾸기 (식탁 주문 사이즈)

프레임은 그대로 두고 상판만 1600 → 1800, 2000, 2200mm처럼 바꿀 때 써요.

1. 상판을 클릭해서 그룹으로 만들어요. (보통 이름이 ‘상판’으로 붙어요)
2. 3번 아래 **크기 바꾸기** 칸에 `1800×900, 2000×1000, 2200`처럼 적고 ‘추가’를 눌러요. 깊이를 안 적으면 지금 깊이 그대로예요.
3. 크기 칩을 누르면 3D 화면과 치수선이 그 크기로 바뀌어요.
4. 질감·색도 고르면 크기 × 재질 조합마다 파일이 생겨요. (3개 크기 × 2색 = 6개)

모서리 둥근 부분과 테두리 단면은 모양 그대로 두고 가운데만 늘이거나 줄여서, 상판 모서리가 찌그러지지 않아요.

상판 아랫면이나 얇은 아래층 판처럼 상판과 한 판을 이루는 부분은 따로 고르지 않아도 같은 크기로 같이 바뀌어요(화면에 몇 개가 같이 바뀌는지 나와요). 다리와 프레임은 그대로이고, 아랫면에서 프레임을 감싸는 홈은 프레임 자리에 그대로 남고 그 바깥만 늘어나요.

### 사진으로 재질 만들기

대리석·나무처럼 무늬에 색이 있는 재질은 사진으로 만들어요. 3번의 대리석·나무 탭에서 ‘사진으로 만들기’를 누르고 사진을 넣은 뒤, 사진 가로가 실제로 몇 cm인지 적으면 돼요. 이음매가 안 보이게 다듬고, 요철과 광택도 자동으로 만들어요.

거래처 원단·가죽 사진은 ‘질감만 쓰고 색은 hex로’를 고르면, 같은 질감을 여러 색으로 쓸 수 있어요.

- **무늬 진하기**: 사진 속 얼룩과 명암을 얼마나 살릴지예요. 가죽·원단은 연하게 시작해요. 너무 얼룩덜룩하면 왼쪽으로 내려요.
- 미리보기는 비스듬히 빛을 비춘 2×2 타일이라 요철·광택까지 보여요. 왼쪽 아래 자(예: 5cm)로 실제 크기를 가늠해요.
- 만든 재질은 카드에 마우스를 올리면 나오는 **×** 로 지울 수 있어요. 한 번 더 확인한 뒤에 지워요.
- 만든 재질을 고치려면 카드의 **✎**, 색 고르는 칸의 **재질 수정**, 또는 ‘재질·색 관리’의 **수정**을 눌러요. 만들 때 창이 그 값 그대로 열려요. **수정 저장**은 그 재질을 쓰는 변형과 3D 화면에 바로 반영되고, **새 재질로 저장**은 사본을 만들어요.
- v0.3부터는 원본 사진도 재질과 함께 저장돼서 모든 값을 다시 바꿀 수 있어요. 그 전에 만든 재질은 크기·요철·광택·이름만 바뀌고, 같은 사진을 다시 넣으면 전부 바꿀 수 있어요.

만든 재질과 저장한 색, 모델별 작업 기록은 그 PC의 브라우저에 남아요. 새 버전 파일로 바꿔 열어도 같은 브라우저라면 그대로 보여요. 다른 PC로 옮길 때는 **재질·색 관리 → 내보내기**로 .zip을 만들어 그 PC에서 **가져오기** 하세요.

### 작업 이어서 하기

- 모델마다 하던 작업(나눈 부분, 그룹, 고른 재질·색, 크기, 압축 설정)을 자동으로 기억해요. 같은 GLB 파일을 다시 열면 2번 칸에 ‘지난번 작업을 이어서 열었어요’가 나오고 그대로 이어져요. 파일 이름과 용량이 같으면 같은 모델로 봐요.
- 처음부터 다시 하려면 그 옆의 **처음부터 하기**를 눌러요. 사진으로 만든 재질과 저장한 색은 지워지지 않아요.
- 작업 기록도 그 PC의 브라우저에 남아요. **재질·색 관리 → 내보내기**로 만든 .zip에 같이 들어가서, 다른 PC에서 가져오기 하면 거기서도 이어서 할 수 있어요.

### 제품 사진, 변형 목록, 카탈로그

- 내보내기의 **제품 사진도 같이 저장**이 켜져 있으면, 변형마다 사진을 GLB와 같은 이름으로 함께 저장해요. ‘사진·파일 이름 설정’에서 고를 수 있어요.
  - **각도**: 지금 보는 방향 / 정면 / 45° / 옆. 여러 개를 고르면 변형마다 그만큼 찍고 이름 끝에 `_정면`, `_45도`, `_옆`이 붙어요.
  - **배경**: 투명(PNG) 또는 흰색(JPG). **크기**: 1600×1200, 2000×1500, 1200×1200, 2000×2000.
  - **목록용 썸네일**(480px)도 같이 만들 수 있어요.
- 폴더나 ZIP에는 **변형목록.csv**(엑셀)와 **변형목록.json**(웹 서비스 등록용)도 들어가요. 파일마다 크기(W·D·H), 그룹별 재질·재질 ID·색 이름·색 코드·크기, 용량, 삼각형 수, 텍스처, 검사 결과가 한 줄씩 나와요.
- **카탈로그 HTML**: 변형마다 사진·재질·색 코드·크기·파일 이름이 카드로 정리된 한 장짜리 파일이에요. 더블클릭하면 브라우저에서 열리고 인쇄도 돼요. 영업·상품팀에 공유할 때 써요.
- 3D 화면 위의 **사진 저장**은 지금 보이는 모습을 바로 한 장 저장해요. **원본 보기**를 누르면 바꾸기 전 모습이 나와서 비교할 수 있어요.

### 파일 이름

- 기본은 그룹·재질 이름 그대로예요: `소파__쿠션-무광-가죽-코냑-8B4A22__다리-블랙-메탈-1D1C1B.glb`
- **영문 (재질 ID·색 코드)** 을 고르면 영문·숫자·`_`·`-`만 써요: `sofa__g1-leather-matte-8B4A22__g2-metal-black-1D1C1B.glb`. 웹 서비스나 해외 마켓은 보통 이런 이름을 요구해요. 그룹 이름이 한글이면 `g1`, `g2`처럼 번호가 되고, 한글 이름은 CSV·JSON에 같이 적혀요. ‘파일 이름 앞부분’도 영문으로 넣어 주세요.

### 결과 파일과 검사

- GLB(glTF 2.0)이고 1 단위 = 1 m 실제 크기, 바닥 가운데가 원점(0, 0, 0), Y가 위예요. 가구 밑면은 바닥에서 10mm 위(내보내기의 ‘바닥에서 띄우기’, 0이면 딱 붙음)라 공간의 바닥이나 러그에 묻히지 않아요. Khronos 3D Commerce 자산 제작 지침과 같은 규격이라 공간무드와 대부분의 3D 뷰어·AR에 바로 들어가요. 앞면 방향은 원본 모델 그대로예요.
- 모양은 meshopt(EXT_meshopt_compression + KHR_mesh_quantization), 텍스처는 WebP로 압축해요. three.js·model-viewer·Babylon 기반 뷰어는 바로 열어요.
- 다른 프로그램에서 안 열리거나 텍스처를 PNG·JPG로 요구하는 마켓(아마존 등)에 올릴 때는 **호환 모드**를 켜세요. (텍스처가 JPG가 되고 압축을 덜 해서 용량이 커져요)
- 저장한 파일마다 **검사 결과**가 내보내기 아래에 나와요: 삼각형 수, 텍스처 수와 최대 크기, 그리고 프로그램 안에 들어 있는 Khronos glTF 공식 검사기(glTF Validator)의 결과예요. 오류가 있으면 ✗로 표시돼요. ⓘ는 공간무드에는 문제없지만 해외 마켓 기준을 넘는 경우예요: 삼각형 20만 개(아마존 가구), 15 MB(Shopify는 자동 재압축), 텍스처 4096 px 초과, WebP 텍스처. 자세한 내용은 줄에 마우스를 올리거나 CSV·JSON의 ‘검사’·‘참고’ 칸을 보세요.
- 압축 품질·텍스처 크기·호환 모드·사진·파일 이름 설정은 이 PC에 기억돼요. 모델별 작업 기록에 저장된 압축 설정이 있으면 그 모델에서는 그 값이 먼저예요.
- 화면 오른쪽 위 **도움말**(F1)에 사용 순서, 마우스·키, 저장 파일 규격, 자주 묻는 질문이 있어요.

## 구성 (개발용)

| 폴더 | 내용 |
| --- | --- |
| `app/` | 프로그램 화면(`main.js`, `viewer.js`), 백그라운드 처리(`worker.js`), 사진 재질(`photo.js`), 저장(`store.js`) |
| `core/segment.js` | 자동 부분 나누기. 방석과 프레임이 만나는 오목한 홈, 색이 바뀌는 곳, 몸체 밑면 아래의 다리·받침대를 따라 자른다. |
| `core/uvbox.js` | 실제 크기 기준 텍스처 좌표(가죽 결·원단 짜임 크기가 어디서나 같게). |
| `core/size.js` | 실제 크기(W·D·H) 맞추기, 가로·깊이 방향 찾기, 상판 크기 바꾸기(끝은 그대로, 가운데만 늘이기). |
| `core/skin.js` | 부분별 재질 적용, 변형 생성, 압축(meshopt + WebP). 프로그램과 명령줄 도구가 함께 쓴다. |
| `cli/skin.mjs` | 명령줄 도구. |
| `materials/` | 기본 질감 라이브러리(`library.json` + 텍스처). 색은 hex 코드로 곱해서 입힌다. |
| `tools/` | 질감 추가(`add-material.mjs`), 임시 질감 생성(`procedural_textures.py`). |
| `dev/` | 시험 도구: 시험용 가구 만들기, 앱 시험, 실제 모델 점검 (`dev/README.md`). |
| `dist/` | 완성된 프로그램(`skin-studio.html`, 파일 하나). |

```bash
npm install
node app/build.mjs          # dist/skin-studio.html 다시 만들기

# 명령줄 도구 (Node.js 20 이상)
node cli/skin.mjs analyze 소파.glb               # 부분 번호, 크기, 색칠한 미리보기
node cli/skin.mjs run examples/sofa-job.json     # job 파일대로 변형 만들기
node cli/skin.mjs compress 소파.glb --h 812      # 재질은 그대로, 실제 크기로 맞추고 용량만 줄이기
```

### job 파일

```json
{
  "input": "식탁.glb",
  "size": { "w": 1600, "d": 900, "h": 750 },
  "groups": [
    { "name": "상판", "parts": [0],
      "sizes": [ { "w": 1800, "d": 900 }, { "w": 2000, "d": 1000 }, { "w": 2200 } ],
      "choices": [ { "material": "leather-matte", "color": "#8B4A22" } ] }
  ],
  "outDir": "out"
}
```

- `size`: 가구의 실제 크기(mm). `h`는 꼭 넣고, `w`·`d`는 선택이에요(비우면 모델 비율대로). 결과는 미터 단위, 바닥 가운데 기준이에요. 예전 job의 `widthMm`도 그대로 쓸 수 있어요.
- `parts`: `analyze`가 알려준 부분 번호. 그룹에 넣지 않은 부분은 원본 그대로 남아요.
- `sizes`: 그 부분만 크기를 바꿀 때(상판 주문 사이즈). `d`를 빼면 지금 깊이 그대로예요.
- `choices`: 질감과 색. 비우면 원래 모습 그대로 크기만 바꿔요. 파일은 그룹마다 (질감 × 크기)의 모든 조합으로 만들어요.
- `color`: hex 코드(`#8B4A22`) 또는 `library.json` 팔레트의 색 이름(id). `rotate: 35`처럼 각도(도)로 무늬 방향을 돌릴 수 있어요. 재질 정의의 `rotate`(사진 재질의 바로잡기 각도)는 여기에 더해져요.
- `swapAxes: true`: 가로와 깊이 방향이 반대로 잡혔을 때.
- `liftMm`: 바닥에서 띄우는 높이(mm, 기본 10). 0이면 바닥에 딱 붙어요.

## 현재 상태 (v1.4, 2026-11-03)

- v1.4에서 고친 것: ① **상판 크기를 바꾸면 테두리·아랫면이 비어 보이던 문제**. 상판 아래쪽이 따로 나뉜 부분(얇은 아래층 판, 아랫면)은 상판과 함께 늘어나지 않아서, 늘어난 상판 밑이 뚫려 보였어요. 이제 상판과 한 판을 이루는 부분을 찾아 같은 크기로 같이 늘이고(`core/size.js` `slabPlan`·`outputPieces`), 아랫면에서 프레임을 감싸는 홈은 프레임이 있는 가운데를 그대로 두고 그 바깥만 늘여요(`stretchFor`의 `hold`). ② **유광 재질의 반사가 들쭉날쭉하던 문제**(model-viewer 등). 하이그로시·유광 도장·미러·유리(`isGlossy`)를 입힌 부분은 AI 표면의 잔물결을 위치까지 고르게 펴고(`fairSurface`, 면 법선 걸러내기 + 꼭짓점 맞추기, 37° 넘는 모서리는 그대로, 4mm 이내), 파일의 법선을 8비트 대신 10비트로 적어요(meshopt QUANTIZE, 유광 재질이 있는 파일만; 용량 약 +25%). 예전에 저장한 유광 조각은 다시 열어 저장할 때 법선을 한 번 고르게 해요(`normals: 'fine'` 표시). ③ **나무·대리석 상판 옆면의 세로 줄무늬**. 무늬를 90° 돌리면 긴 옆면의 결이 세로로 서서 테두리가 거칠게 보였어요. 이제 나무·대리석은 윗면 무늬를 모서리 너머로 접어 옆면에 이어 붙여요(`uvFold`).

- v1.3.2: 바닥에서 30mm 띄워 다시 저장한 식탁이 공간무드에 안 보였어요. 20mm 파일과 30mm 파일은 노드 높이 9바이트만 다르고 용량이 바이트까지 같았고, 메모 한 줄만 더해 용량을 바꾼 30mm 파일은 잘 보였어요(sunny 확인). 그래서 저장 파일마다 `asset.extras`에 저장 정보(`app`, `savedAt`, `floorGapMm`, `file`)를 적고, 이 PC에서 같은 모델로 저장한 파일과 용량이 같으면 `pad`로 늘려 겹치지 않게 해요(압축 데이터는 그대로, JSON 부분만). v1.3.1의 20mm 제한(잘못 짚은 원인)은 풀었어요.
- v1.3에서 고친 것: 공간무드에서 **가장자리·테두리가 깨져 보이던 문제**. 삼각형을 줄일 때 위치만 보고 면의 방향(법선)은 무시해서, 유광 부분의 반사광이 들쭉날쭉하고 새 재질 상판의 테두리가 울퉁불퉁하게 비쳤어요. 이제 ① 법선도 함께 지키며 줄이고(같은 삼각형 수·용량), ② 새 재질 부분은 원래의 촘촘한 표면에서 법선을 구해 AI 표면의 잔물결을 다듬고(30° 넘는 진짜 모서리는 그대로), ③ 테두리 근처에서 무늬 투영 방향이 조각조각 바뀌어 점처럼 끊기던 곳(5cm² 미만 조각)을 주변 방향으로 합쳐요. 저장할 때 자동이에요.

- v1.2에서 고친 것: 실제 크기를 넣을 때 **원래 비율 유지**가 기본이에요(하나만 넣으면 나머지는 비율대로, 한 배율로 키움). 예전에는 W·D·H를 모두 넣으면 축마다 따로 늘여서 비스듬한 식탁 다리의 각도가 바뀌었어요. 비율을 풀면 얼마나 늘어나는지 경고가 나와요. 예전에 늘어난 치수로 기억된 모델은 원래 비율로 다시 열고 안내해요. 치수 기억이 파일 이름만으로 되어 있어서 이름이 같은 다른 GLB(예: Untitled.glb)에 예전 치수가 붙던 문제도 고쳤어요(이름 + 용량).

- v1.1에서 넣은 것: 저장 파일을 바닥에서 10mm 띄우기(내보내기의 ‘바닥에서 띄우기’, 0~100mm, 설정 기억; 원점은 그대로 바닥 가운데, 치수 H는 그대로; JSON `floorGapMm`). 무늬 방향을 부분마다 임의 각도로(슬라이더·숫자·기본/90° 버튼, 3D 화면에 즉시 반영), 사진 재질의 ‘무늬 바로잡기’(만들기·수정 창에서 2×2 미리보기로 확인, 재질에 저장되어 어느 부분에 써도 적용). 변형 목록 JSON에 `patternDeg`(부분 각도)와 `material.rotate`(재질 보정), CSV ‘참고’에 `무늬 N°`가 기록돼요.
- v1.0에서 넣은 것: 저장 파일 검사(통계 + Khronos glTF Validator), 제품 사진 설정(각도·배경·크기·썸네일), 카탈로그 HTML, 변형 목록 JSON, 영문 파일 이름, 설정 기억, 도움말 창.
- 기본 질감은 계산으로 만든 procedural 재질이에요. 거래처 원단·가죽 사진이 정리되면 ‘사진으로 재질 만들기’로 진짜 질감을 넣어요.
- 그대로 두는 부분(예: 프레임)은 원본의 잘게 나뉜 텍스처 좌표 때문에 삼각형을 더 줄이기 어려워요(보통 변형 하나에 50만~70만 개). 해외 마켓의 20만 개 기준이 꼭 필요해지면 원본 텍스처를 새 좌표로 옮겨 굽는 기능이 필요해요.
- 넣지 않은 것: 한 파일에 여러 색상을 담는 KHR_materials_variants(보는 쪽의 지원이 필요하고 공간무드는 파일 하나 = 상품 하나), 앞면을 +Z로 자동 회전(앞면 추정이 틀릴 수 있음), 여러 파일 한꺼번에 압축(파일마다 실제 높이가 필요), USDZ 저장.
